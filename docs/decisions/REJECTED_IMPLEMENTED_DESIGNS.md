# 已踩坑与不再恢复的实装设计

日期：2026-05-16

性质：负面决策 / 防回滚记录。

本文件记录已经实装、半实装或被认真展开过，但后来确认不适合继续恢复的设计。它的作用不是否定当时的探索价值，而是避免后续会话被旧文档、旧提交或“看起来也许还能救”的想法带回同一条路。

如果本文件与旧的讨论文档冲突，以本文件为准。除非之后明确重新开题，否则不要把这里的内容当作待办重新实现。

## 1. 本轮明确记录的坑

### 1.1 阵型系统：扇阵作为独立第三阵型

结论：`扇阵`不再作为默认独立阵型恢复。阵型系统后续应收敛到两个可控阵型的切换，优先保留：

- `环阵`：近身护体、解压、贴脸威胁处理。
- `贯穿阵`：远距破线、高价值目标、Boss 窗口输出。

不要再恢复的形式：

- `环阵 / 扇阵 / 贯穿阵` 三阵型常规切换。
- `Space` 在三个阵型里循环。
- 把扇阵作为单独教学波、单独解锁层、单独资源判断层。
- 用“中距离面扫”作为第三阵型存在的主要理由。

允许保留的形式：

- 某些攻击、特效或轨迹可以有扇面视觉。
- 中距离压力可以通过敌人构图、飞剑散布、贯穿阵派生表现或环阵外缘表现解决。
- 但这些都不应重新变成独立阵型身份。

踩坑原因：

- 三档距离让玩家在持续战斗中承担过高的控距税。
- 扇阵的中距离身份很容易同时挤压环阵和贯穿阵，导致职责边界变糊。
- 教学、UI、解锁和调参成本都会被第三阵型放大。
- 连续变形本来是项目的手感资产，但三阵型切换会把它推向解释系统，而不是战斗直觉。

历史线索：

- `bbc5708` 曾加入手动剑阵控制，最早是 `环阵 / 贯穿阵` 两态切换。
- `8120fcc` 又把 `扇阵`放回手动切换与教学解锁链路。
- 2026-05-16 重新确认：这属于近期反复踩坑方向，不应继续作为目标方案恢复。

### 1.2 剑灵、剑相与武器锻造系统

结论：不要在当前阶段恢复完整的 `剑灵 + 武器锻造 / 剑相`系统。

不要再恢复的形式：

- 让剑灵替玩家选择阵型、索敌或决定战斗策略。
- 用材料、性格、剑相把普攻、御剑、环阵、扇阵、贯穿阵等动作全部展开成组合矩阵。
- 先做四把验证剑，再反推一整套养成系统。
- 把飞剑从“玩家操作的身体延伸”变成“系统替玩家表演的伙伴 AI”。

允许保留的形式：

- 剑可以有名字、气质和轻量叙事。
- 锻造可以暂时作为美术、命名或关卡奖励概念保留。
- 只有当核心战斗已经稳定后，才允许重新讨论极小范围的手感差异。

踩坑原因：

- 这个方向把问题从战斗手感拉向养成系统，体量迅速膨胀。
- 每个剑相都要求影响多个动作，组合复杂度过高。
- 剑灵如果参与战斗决策，会削弱玩家对御剑和阵型的掌控感。
- 它会诱导我们用系统层解释取代当下最重要的输入可信度、节奏和读感。

历史线索：

- `86c9d22` 与 `36b61e2` 展开了飞剑锻造、剑相和剑灵讨论。
- `8120fcc` 加入了锻造攻击形态 mockup。
- 当前代码搜索没有发现剑灵/锻造已经成为主战斗脚本的稳定实装，因此这条按“已展开过但不再推进的系统坑”归档。

## 2. 从项目历史中搜到的实装后移除/禁用内容

### 2.1 冻结弹幕 -> 主动吸收 -> 再发射

状态：已从当前核心循环中移除。

历史线索：

- `c2df265` 调整过自动吸收与发射控制。
- `44b9d52` 又回退到原型操作映射，恢复 `Space` 吸收、左键发射的结构。
- `334e8f9` 把当前设计改写为“不再是冻结弹幕 -> 主动吸收 -> 再发射”，并明确记录已移除 `冻结弹幕`、`主动吸收`、`吸收后围绕玩家的弹丸库存`。

不要恢复的原因：

- 弹丸库存会把“剑修御剑”的核心幻想转移成“管理敌弹资源”。
- 主动吸收增加额外输入税，战斗节奏容易变成先处理资源再允许出招。
- 后来的常驻可见飞剑库存更贴题，也更直接支撑剑阵读感。

### 2.2 `Q` 必杀：全屏清弹、范围伤害、Boss 窗口绕过

状态：已移除。

历史线索：

- 早期 Godot 和 Web 原型都有 `Q 必杀`。
- `d233d38` 从 `attack_profiles.gd`、`main.gd`、Web 原型和当前设计文档中移除了 `ultimate` / `Q 必杀`。

不要恢复的原因：

- 它绕过 Boss 受击窗口，会削弱 `Puppet / Silk` 机制的识别价值。
- 它像一个外接清屏按钮，不像御剑、近战或剑阵自然长出来的动作。
- 它和剑意资源绑定后，会把剑意的含义从战斗节奏变成攒大招。

### 2.3 剑丸资源与 `Space` 强化剑技

状态：实装过，后续从主循环代码中移除。

历史线索：

- `99630fe` 实装了 `SWORD_RESOURCE`、`array_empower`、剑丸掉落、`Space` 开启强化剑技等逻辑。
- `9a509e9` 继续补了爆发环阵近身清弹。
- `d2745f2` 删除了 `SWORD_RESOURCE_MAX`、剑丸掉落、`_try_activate_array_empower()`、`array_empower_timer` 等主循环实现，改回常规剑阵直接可用。

不要直接恢复的原因：

- 它一度解决了“爆发窗口”的概念问题，但又引入第二资源、掉落节奏、失败反馈和额外 UI。
- 当核心输入还没有完全稳定时，剑丸会把问题转移到经济节奏上。
- 如果以后还需要爆发层，应先证明当前常规循环为什么不够，再做最小原型，不要整套恢复旧实现。

### 2.4 剑阵共鸣 / 余韵连招

状态：实装过，当前被显式禁用。

历史线索：

- `6d1fc47` 添加了剑阵共鸣组合系统文档。
- `1218fd8` 接入 `SwordResonanceController`、`fan_time_stop`、`pierce_time_stop` 等连招表现。
- `8120fcc` 在 `sword_resonance_controller.gd` 中加入 `RESONANCE_ENABLED := false`，所有获取、触发和消耗入口都被禁用。

不要直接恢复的原因：

- 条件触发、余韵时间、形态连招会把战斗读感推向隐藏规则。
- 它叠在阵型系统之上，会进一步放大形态身份和输入税问题。
- 如果当前目标是压缩阵型复杂度，就不应再恢复一个依赖三形态记忆的连招层。

### 2.5 阵型距离引导圈

状态：实现过，当前被显式关闭。

历史线索：

- `1218fd8` 引入阵型距离引导相关显示。
- `8120fcc` 加入 `ARRAY_DISTANCE_GUIDE_ENABLED := false`，并把引导强度归零。

不要直接恢复的原因：

- 它把阵型理解问题视觉化了，但也让画面开始解释系统。
- 当前更应该减少玩家需要读的辅助层，把判断压回动作、飞剑和敌人关系。
- 如果两阵型方向成立，距离引导圈更没有恢复必要。

## 3. 以后重新开题的门槛

上面的内容不是永远禁止想象，而是禁止无意识回滚。若未来确实要重新打开其中任何一项，必须先写清楚：

- 当前版本具体哪个玩家体验问题无法用现有系统解决。
- 为什么旧失败原因这次不再成立。
- 只做哪一个最小可玩原型。
- 成功和失败分别如何判断。

没有这四点，就不要从旧提交或旧文档里恢复这些系统。
