# 项目已定案设计决策

本文件只记录当前已经确认、可以作为实现依据的设计结论。

同时请阅读 `docs/decisions/REJECTED_IMPLEMENTED_DESIGNS.md`。如果旧讨论文档或本文件较早条目与其中的“不要恢复”记录冲突，以最新的负面决策记录为准。

注意：

- 本文件描述的是项目准备收敛到的目标方向
- 当前主场景里已经实际落地的玩法，请优先对照 `docs/project/CURRENT_PROJECT_DESIGN.md`

如果某些条目与当前代码不一致，应先理解为“实现尚未完全跟上定案”，而不是默认代码或文档其中一方已经失效。

## 1. 战斗调优方法

- 战斗讨论默认以玩家实机感受为起点，而不是先从抽象数值出发。
- 每次调优都先判断玩家感受是否正确，再定位系统根因，再决定最小可验证原型。
- 优先保护已经验证有效的爽感，不为了解决一个问题顺手牺牲项目签名体验。

## 2. 当前核心战斗方向

- 核心战斗由 `近战`、`御剑`、`剑阵` 和 `Boss 机制处理` 共同构成。
- `近战`负责贴身兑现、弹反、近身压制与剑意获取。
- `御剑`负责切机制、制造窗口、提供高价值中远程处理。
- `剑阵`保留为持续可见的飞剑形态层。最新收敛方向是弱化第三阵型，把可控阵型压回近身护体与远距破线两类职责。
- 不再把 `Space + 剑丸` 强化剑技作为当前目标方案直接恢复；如果未来需要爆发层，必须重新做最小原型论证。

## 3. Boss / Puppet / Silk 机制

- Puppet 是 Boss 机制体，不是普通敌人。
- Puppet 不显示普通生命条。
- Puppet 不能被飞剑、近战或剑阵当作普通敌人直接击杀。
- Puppet 的主要死亡条件是对应 Silk 被切断。
- 在 `Puppet Ambush` 阶段，清空有效丝线后 Boss 进入脆弱状态。

## 4. 剑阵输入与控制原则

- 不增加新按键。
- 不使用滚轮切换阵型。
- 不采用自动战场判断来代替玩家选择阵型。
- 阵型主导语义仍由“准星与玩家距离”决定。
- 后续目标不再恢复 `扇阵` 作为独立默认阵型；若采用手动切阵，只在 `环阵 / 贯穿阵` 两态之间切换。
- 必须保留当前连续变形的视觉手感，不做整段硬锁阵型。
- 不用“更高纯数值收益”直接补偿操作税，优先修控制结构。

### 4.1 已否决：Jet Lancer Arcade Type 飞行操控

用户已明确否决 Jet Lancer Arcade Type 式御剑飞行操作。

后续不要采用以下方案作为御剑飞行默认操作或主战斗接入方案：

- `A / D` 持续旋转航向或剑首。
- `W` 作为油门式推进。
- 松开 `W` 通过失速 / 收势 / 滑行来缩小转弯半径。
- `S` 作为刹车压弯。
- `Shift` 作为航向推进体系里的 afterburner。
- `Space` 作为飞行翻滚 / 翻锋闪避。
- 攻击方向默认绑定当前航向。

这个方向的问题不是数值没调好，而是操作身体感不符合项目当前目标。它会把御剑推向二维飞机狗斗，并破坏主战斗已有的 `WASD` 走位、右键御剑、鼠标剑阵和 `Space` 强化剑技输入职责。后续御剑飞行应重新从更直接、低负担、符合剑修动作感的控制方式出发。

但 Jet Lancer 的飞行姿态和动画表现可以作为参考：高速前压、急转收势、加速拖尾、残影、镜头速度感、闪避动作读法等表现层经验可以借鉴。借鉴范围只限姿态、动画、VFX、镜头和速度读感，不包含 Arcade Type 操作结构。

## 5. 剑阵视觉层与发射层分离

- `视觉变形`继续使用原始鼠标距离驱动，保持连续、丝滑、可读。
- `发射控制`使用独立的控制距离与控制阈值，降低持续射击中的误切形态。
- 因此，“操作距离”和“战术射程”被明确拆开，不再硬绑定。

## 6. 剑阵形态职责分工

- `环阵`：近距离护身、解压、清周身威胁。
- `贯穿阵`：远距离破线、处理高价值目标。
- `扇阵`不再作为独立默认阵型恢复；如果需要扇面表现，只能作为具体攻击或特效的派生形态，而不是第三个切换身份。

这些职责优先通过：

- 射程层级
- 覆盖方式
- 周转语义
- 稳定性

来区分，而不是只靠面板伤害区分。

## 7. 已归档：剑丸与强化剑技

旧方案曾经是：`Space` 消耗 `1` 个剑丸资源，开启短时强化剑技，攻击型剑阵主要在强化窗口内兑现。

这个方向已经实装过，也已经从主循环代码中移除。后续不要直接恢复旧的 `剑丸掉落 -> Space 强化 -> 强化剑阵`整套实现。

如果未来确实需要爆发层，应先重新说明：

- 当前常规循环无法解决的具体玩家体验问题是什么。
- 为什么不通过近战、御剑或两态剑阵的小改动解决。
- 新爆发层的最小可玩验证范围是什么。

## 8. 日常循环分工

- 日常循环优先由 `近战`、`御剑` 和两态 `剑阵`共同承担。
- `近战`负责建立节奏、处理贴身压力、执行弹反。
- `御剑`负责中远程高价值处理和 Boss 机制处理。
- `剑阵`保留形态读感和持续飞剑库存，但不再以恢复三阵型或剑丸爆发层为目标。
- 如果 `御剑` 与 `剑阵`再次争夺同一个主动输出位，先修职责、输入和反馈，不用新增资源层来绕开问题。

## 9. 剑阵可读性与战场信息量

- 剑阵飞剑必须作为可见实体存在，不退回为纯数字库存。
- 场上允许出现可见缺口，用于传达当前可用飞剑数量。
- 飞剑返航连线不作为正式战斗表现保留。
- 阵型预览不常驻，只在蓄阵时显示。
- UI 和场上图形的首要目标是服务战斗读感，而不是解释系统。

## 10. 当前已定案的飞剑行为原则

- 飞剑不能“碰一下就立刻折返”。
- 飞剑射出后至少完成最小出击距离，再允许返航。
- 命中后仍应保留短掠进或后续前飞，而不是立即失去出击价值。
- 不同阵型可以在未来拥有不同的回收语义，但当前统一原则是：先完成一次有效出击，再回收。

## 11. 当前已定案的射程层级

- 环阵必须保持最近。
- 贯穿阵保持最远。
- 不再为 `扇阵` 单独保留中程层级；中距离压力优先交给敌人构图、飞剑散布或两态派生表现。
- 环阵即使更容易维持，也不能因此获得过长的实际攻击距离。

## 12. 当前已验证的环阵调优方向

- 环阵的问题优先通过“更近、更稳、更能清周身威胁”解决，而不是先加远程能力。
- 环阵的可靠性优先来自更近的出击目标、更短射程、更强近身命中宽度与贴脸威胁处理能力。
- 环阵是两态阵型里的近身护体兑现层，不再依赖 `强化剑技` 才成立。
- 环阵可以拥有克制的近身解压能力，但不能替代普通攻击弹反的核心生存职责。
- 后续环阵优化重点转向近程护身表达、贴脸可靠性和周身压力读感。

## 13. 技能不可释放反馈原则

- 当 `御剑` 或 `剑阵` 因资源、距离或库存条件不足而无法释放时，必须提供即时可读的反馈。
- 不同失败原因应尽量可区分，至少要区分：
  - `剑意不足`
  - `剑阵飞剑库存不足 / 正在回收`
- 这类反馈不应完全依赖玩家自己盯数值条推断，最好同时具备明确的 UI、状态提示或其他即时表现。

当前实现已经采用：

- 状态文字提示
- 对应 HUD 行的短促闪烁染色
- 失败提示节流，避免长按时刷屏

后续如仍然不够直观，再考虑补失败音效或更强的局部 UI 动效。

## 14. 已归档：剑丸经济节奏

剑丸产出、剑丸掉落频率和强化窗口经济已经归档，不再作为当前实现依据。

不要通过恢复剑丸经济来解决：

- 阵型身份不清。
- 剑阵和御剑抢输出位。
- 爆发感不足。
- 玩家不理解当前资源反馈。

这些问题应先在现有动作职责、输入可信度和战斗读感里解决。

## 15. 普通攻击弹反手感原则

- 普通攻击弹反出去的子弹必须足够快，读感应接近“斩开后立刻反杀”。
- 如果弹反看起来拖沓，优先提高反弹子弹速度，先修观感和兑现速度，再考虑其他数值。

## 16. 锻造词条与动态战斗适配原则

- 本项目的战斗问题会在短时间内动态切换，玩家不可能为“弹反、清压、补刀、破势、接御剑或接剑阵”频繁更换武器。
- 因此，锻造词条不应把一把剑设计成只服务某个固定战斗动机的工具，而应采用“基础职责固定，物理偏向改变解法”的结构。
- 所有剑的普通攻击都必须保留基础职责：斩弹保命、近身处理、命中或弹反回剑意、为御剑和剑阵创造节奏入口。
- 词条只能改变完成这些职责的方式与战斗气质，例如惯性与承诺感、空间投射形态、剑气组织方式，而不能替换或废掉基础职责。
- 后续设计 `长锋 / 阔刃`、`凝锋 / 分光`、`轻灵 / 重势` 等词条时，应优先判断：它是否让同一个左键动作以不同身体结构完成相同基础职责，而不是让某把剑失去可靠弹反、近身处理或资源建立能力。
- 判定层需要保底战斗可信度：例如长锋伤害形态可以更细长，但斩弹不能随之变成不可靠；凝锋可以合成一刀，但不能让玩家在弹幕压力下不敢使用普通攻击；重势可以更慢，但必须用读感、打击反馈和相称收益补回承诺成本。
