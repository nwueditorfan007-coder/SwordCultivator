# 御剑大战场背景改造方案：Jet Lancer 参考落地版

- 日期：`2026-05-31`
- 状态：讨论稿，可作为下一轮原型任务拆分依据
- 目标场景：`res://scenes/prototypes/YujianSpriteSequencePrototype.tscn`
- 主要脚本：`res://scripts/prototypes/yujian_sprite_sequence_prototype.gd`

## 1. 核心结论

Jet Lancer 对本项目最有价值的不是飞机操控，而是它的大战场背景组织方法：

- 大面积低信息底色给高速角色、弹道、敌人留出读性。
- 地平线、城市、海面、跑道、云层只负责空间尺度和关卡气质，不抢战斗主体。
- 速度感主要由拖尾、弹道弧线、近景短线、镜头和目标运动给出，而不是让背景全屏高速滚动。
- Boss 或大型目标用高对比剪影压住画面，背景在它后面主动退让。

转译到《SwordCultivator》时，应改成：

**云海天幕 + 远山墨带 + 稀疏仙域地标 + 近景云缕速度参照 + 法阵/云海边界。**

不要转译成现代城市、飞机跑道或 Jet Lancer 式狗斗地图。也不要恢复 Jet Lancer Arcade Type 操控。

## 3. 从 Jet Lancer 抽出的可用规律

### 3.1 背景大多是低频大色块

官方截图里常见构图是：天空、海面、远城、跑道或夕阳占据大面积画面，但这些区域的纹理频率很低。玩家飞机、导弹、白色弧线、敌方大型黑色结构因此能很快被读出来。

对本项目的意义：

- 天幕和云海要先做成大色块，不要一开始就堆复杂云纹。
- 远山和仙域地标只能用低透明、低对比形状。
- 御剑人物、飞剑、弹幕、敌人、丝线、Boss 机制必须永远比背景更硬、更亮或更黑。

### 3.2 地平线给方向感，但不参与战斗判断

Jet Lancer 的城市、海平线、跑道通常贴在中下部或远处。它们让玩家知道自己在高速穿过一个大空间，但不会成为可碰撞平台或具体导航目标。

对本项目的意义：

- 可以保留横向大战场读法：远山和云海横向铺开，镜头移动时产生慢视差。
- 不要画太多像平台、墙、道路的实体，否则玩家会误以为可以碰撞或需要绕行。
- 现有边界框应该从调试矩形替换成云海结界、远处法阵边、天穹压线这类题材化边界。

### 3.3 速度感来自近景短参照，不靠背景乱滚

Jet Lancer 的速度读感主要来自飞机拖尾、导弹轨迹、白色运动弧线、爆炸残片和目标相对运动。背景本身通常不需要高速滚动，否则会让弹幕变脏。

对本项目的意义：

- 现有 `scene_speed_streaks` 是正确方向，应该保留。
- 现有 3D 风带只适合表现稳定航道的空气流形，不适合在急转时追着玩家转。
- 近景云缕可以作为低透明速度参照，但只在高速或稳定航道时出现，悬停时应该安静。

### 3.4 关卡身份靠少量地标，而不是满屏装饰

官方截图里城市、海面、夕阳、跑道、航母等元素会迅速告诉玩家场景身份，但画面不会到处摆满小物件。

对本项目的意义：

- 每个背景主题只放 1-2 类地标，例如远处剑峰、悬空山、云中塔、破碎阵盘。
- 地标只在远景或中景慢速视差层出现。
- 地标不要贴近角色，不要和飞剑、丝线、敌弹同色同亮度。

## 4. 当前原型背景现状

`yujian_sprite_sequence_prototype.gd` 已经有可用基础：

- `_draw_background()`：纯色天幕、两层山带、世界网格。
- `_draw_parallax_mountain_band()`：远山/中山视差带。
- `_draw_world_guides()`：大世界网格和调试边界框。
- `_create_reference_vfx_viewport()`：透明 3D SubViewport 合成层。
- `_create_reference_fog_cards()`：3D 雾卡片。
- `_create_reference_wind_ribbon()`：稳定航道风带。
- `_update_scene_speed_streaks()` / `_draw_scene_speed_streaks()`：2D 世界空间短白线。

问题也比较明确：

- 当前背景仍有调试场味道，网格和矩形边界比题材化场景更显眼。
- 山带只有两层，能提供视差，但还没有“云海中的大战场”身份。
- 3D 雾卡片和风带已经接入，但缺少统一的背景层级规范。
- 背景主题、速度参照、边界表现、读性验收还没有写成一个可调系统。

## 5. 目标玩家感受

玩家应该感觉到：

- 自己不是在小房间里横移，而是在很大的云海战场中御剑。
- 高速时空间从身边掠过，但眼睛仍能抓住人物、飞剑、敌弹和目标。
- 悬停时画面安静，有高空、云海、远山的呼吸感。
- 急转时主要读到人物压身、剑尾弧线、短速度线，不读到整张背景乱甩。
- 到边界时像触到云海结界或天幕边缘，而不是撞到调试矩形。

玩家不应该感觉到：

- 背景比敌人和飞剑更抢眼。
- 云层、地标或网格像可碰撞地形。
- 高速移动靠花屏和晃动制造刺激。
- 御剑变成 Jet Lancer 式飞机狗斗。

## 6. 推荐背景层级

### L0 天幕底色

职责：

- 给整体空间一个稳定、干净的底。
- 保护弹幕、角色、飞剑读性。

实现：

- 继续在 `_draw_background()` 中先画满屏底色。
- 从当前灰青底色升级为轻微纵向色带：上方偏冷青，下方偏暖白或淡金。
- 可以先用 6-10 个横向 `draw_rect` 叠色实现，不急着写 shader。

建议初始参数：

- 顶部：冷青灰 `Color(0.48, 0.67, 0.72, 1.0)`
- 中部：淡天青 `Color(0.66, 0.78, 0.80, 1.0)`
- 底部：淡云白 `Color(0.86, 0.91, 0.86, 1.0)`
- 整体避免过饱和蓝色，因为飞剑灵光、弹幕和 UI 已经会用高亮色。

### L1 远山墨带

职责：

- 给横向大战场一个远距离地平线。
- 保留 Jet Lancer 式横向空间感，但换成修仙题材。

实现：

- 保留 `_draw_parallax_mountain_band()`，但把山形改得更像水墨远山，而不是普通锯齿山。
- 新增 1 层更远、更淡的山影，视差低于当前远山。

建议初始参数：

- 超远山：parallax `0.035`，alpha `0.10-0.14`
- 远山：parallax `0.075`，alpha `0.16-0.20`
- 中山：parallax `0.16-0.20`，alpha `0.22-0.30`

### L2 云海大块

职责：

- 让战场从“有山的背景”变成“云海上空”。
- 给玩家高度感和修仙题材感。

实现：

- 新增 `_draw_cloud_sea_band()`，用多段低频曲线和半透明白灰色带画出云层。
- 云海主要放在画面下半段和远景，不要满屏覆盖。
- 云海位置用 `camera_center` 做低视差漂移。

建议初始参数：

- 远云 parallax `0.10`，alpha `0.10-0.18`
- 中云 parallax `0.28`，alpha `0.14-0.24`
- 曲线宽大、少节点，避免变成噪点纹理。

### L3 稀疏仙域地标

职责：

- 给大战场记忆点和尺度参照。
- 不参与碰撞和战斗判断。

首批只做程序化剪影，不引入大图资产：

- 远处悬浮剑峰。
- 云中塔影。
- 破碎阵盘弧线。
- 极远处飞舟/仙门小剪影。

实现：

- 新增 `_draw_far_landmarks()`。
- 用 deterministic hash 按世界坐标 tile 生成少量地标。
- 每个屏幕最多可见 `1-3` 个地标。
- 地标 alpha 控制在 `0.08-0.18`，轮廓不要超过敌人和角色对比度。

### L4 近景云缕

职责：

- 高速时提供掠过参照。
- 悬停时减少或淡出，避免画面躁动。

实现：

- 复用现有 `_draw_cloud_wisp()`，但改成世界空间生成，而不是固定屏幕装饰。
- 云缕根据 `velocity.length()`、`throttle_energy`、`carve_energy` 控制生成和透明度。
- 与 `scene_speed_streaks` 分工：云缕慢、宽、柔；速度线短、白、利。

建议：

- 低速：几乎不可见。
- 巡航：少量低透明云缕。
- Boost：云缕加长但 alpha 仍低。
- 急转：不要瞬间转向追随玩家，避免和剑尾弧线打架。

### L5 速度线与稳定风带

职责：

- 速度读感主力。
- 只服务玩家飞行状态，不负责背景身份。

保留现状：

- `scene_speed_streaks` 继续画世界空间短白线。
- `wind_ribbon` 继续只在稳定航道出现。
- 急转、carve、方向切换时停发风带，让人物、飞剑、弧线承担读法。

需要微调：

- 速度线 alpha 不要超过飞剑主体亮度。
- 风带不要出现在角色正后方形成“另一条剑/另一层披风”的误读。

### L6 边界表现

职责：

- 把当前调试矩形变成题材化云海结界。
- 告诉玩家这里是战场边缘，但不把边界画成硬墙。

实现：

- 新增 `_draw_battlefield_boundary()` 替代正式模式下的矩形 debug 边界。
- 距离边界较远时只显示极淡云墙或天幕压线。
- 玩家进入 `BOUNDARY_SOFT_MARGIN` 后，提高边界亮度，出现淡金/青白法阵纹。
- 保留 debug 网格和矩形，但放到 `show_debug_guides` 开关下。

## 7. 第一阶段最小可玩改造

第一阶段目标不是做完整背景系统，而是把“调试场”变成“可试玩的云海大战场”。

### 任务 A：整理背景绘制入口

在 `yujian_sprite_sequence_prototype.gd` 中把 `_draw_background()` 拆成清晰顺序：

```gdscript
func _draw_background() -> void:
	_draw_sky_wash()
	_draw_far_mountain_layers()
	_draw_cloud_sea_layers()
	_draw_far_landmarks()
	_draw_near_cloud_wisps()
	_draw_battlefield_boundary()
	if show_debug_guides:
		_draw_world_guides()
```

第一阶段可以不新建脚本，先在当前原型内实现，降低接线成本。等稳定后再抽成 `YujianBattlefieldBackground2D`。

### 任务 B：加入题材化云海

新增：

- `_draw_sky_wash()`
- `_draw_cloud_sea_layers()`
- `_draw_cloud_sea_band(...)`

验收：

- 不按 `Space` 悬停时，画面已经读作云海/远山/高空，而不是纯调试背景。
- 角色缩小后仍能和背景分开。

### 任务 C：把网格降级为调试层

新增：

- `var show_debug_guides := false`
- `F9` 或现有调试面板开关：显示/隐藏网格和矩形边界。

验收：

- 默认试玩看不到网格。
- 需要调边界时仍能打开网格。

### 任务 D：替换边界框

新增：

- `_draw_battlefield_boundary()`
- `_draw_boundary_edge(...)`
- 用 `boundary_energy` 或玩家到边界距离控制边界 alpha。

验收：

- 玩家接近边界前不被硬线打扰。
- 接近边界时能感到被云海/结界推回。

### 任务 E：补少量远景地标

新增：

- `_draw_far_landmarks()`
- `_draw_landmark_sword_peak(...)`
- `_draw_landmark_array_arc(...)`

验收：

- 高速横向飞行时偶尔经过远景地标，战场显得更大。
- 地标不会和敌人、丝线、飞剑混读。

## 8. 第二阶段：主题与战斗接入

第一阶段通过后，再做主题和战斗态变化。

### 8.1 背景主题

建议先做 3 个主题，不要一开始做很多：

- `CloudSeaDawn`：默认云海晨光，适合普通飞行测试。
- `InkStorm`：灰青墨云，适合 Boss / Silk 压力。
- `SunsetGold`：夕照云海，适合高速试飞和视觉冲击演示。

主题只改变：

- 天幕色带。
- 山带色相与 alpha。
- 云海颜色。
- 地标类型权重。
- 边界法阵颜色。

不改变：

- 玩家控制。
- 镜头逻辑。
- 敌人判定。
- 速度线和风带的核心规则。

### 8.2 战斗态响应

后续接主战斗时，背景可以轻微响应状态：

- 御剑子弹时间：背景饱和度降低，云海流速减慢。
- Boss 闭窗：远山偏冷，场景压暗。
- Boss 开窗：远处云层露出淡金裂光，但不能盖住 Boss。
- Silk 机制：丝线应在背景上方有明确高对比，不让云纹穿帮。

## 9. 读性与性能验收

### 9.1 人工读性测试

每次背景改造后至少录或截 4 个状态：

- 悬停。
- 巡航。
- Boost 高速。
- 高速急转 / carve。

每张图检查：

- 1 秒内能否找到人物。
- 1 秒内能否判断飞剑朝向。
- 弹道/丝线/敌人是否比背景更清楚。
- 背景是否暗示了可碰撞平台或墙。
- 边界是否像题材化边界，而不是调试框。

### 9.2 实机手感测试

要问玩家的不是“背景好不好看”，而是：

- 悬停时有没有高空御剑的空间感？
- Boost 时有没有速度感？
- 急转时眼睛会不会被背景拖走？
- 背景有没有影响敌弹和飞剑读性？
- 战场是否显得变大，而不是只是镜头拉远？

### 9.3 技术检查

推荐验证：

```powershell
.\tools\start_godot_with_log.ps1 -Mode run -Headless -Wait -ExtraArgs @('--quit-after','3','res://scenes/prototypes/YujianSpriteSequencePrototype.tscn')
.\tools\show_godot_errors.ps1 -Tail 220
```

如果只改文档或注释，不需要跑 Godot。改脚本后必须跑。

性能注意：

- 第一阶段优先用 `CanvasItem._draw()` 程序形状，不引入大贴图。
- 地标使用 tile/hash 程序生成，避免每帧分配大量数组。
- 3D SubViewport 已经存在，第二阶段前不要再增加新的 SubViewport。
- 背景数组和点列如果每帧分配太多，再考虑缓存可见 tile。

## 10. 不做清单

本方案明确不做：

- 不引入 Jet Lancer 的飞机操控。
- 不把 `WASD` 改成航向驾驶。
- 不把 `Space` 改成翻滚/闪避。
- 不使用 Jet Lancer 官方截图作为运行时素材。
- 不做现代城市/跑道/机库题材。
- 不把背景做成高细节插画墙纸。
- 不让远景地标变成可碰撞平台。
- 不让风带在急转时持续追着玩家转。

## 11. 建议实施顺序

1. 文档确认本方案的目标感受和边界。
2. 在当前原型脚本内完成第一阶段 A-D。
3. 用默认云海主题试玩悬停、巡航、Boost、急转。
4. 如果读性通过，再做地标 E。
5. 第一阶段稳定后，再抽 `YujianBattlefieldBackground2D` 独立脚本。
6. 第二阶段再做主题切换和战斗态响应。

## 12. 一句话验收标准

成功的版本应该让玩家说：

**“我是在云海大战场里御剑高速穿行，而且我仍然看得清飞剑、弹幕和目标。”**
