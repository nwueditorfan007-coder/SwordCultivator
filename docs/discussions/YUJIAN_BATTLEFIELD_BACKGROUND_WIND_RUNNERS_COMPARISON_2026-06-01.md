## 1. 结论

玩家看到的穿帮是成立的：它不是单纯“透明度还要低一点”的问题，而是中景 / 近景素材正在承担不适合它们的循环职责。

当前画面里，远景云海和山带可以低透明平铺，但带有明确形状记忆的中景山、岛链、云块、近景云缕，一旦以整张贴图或整格 atlas 在画面中央反复出现，玩家就会先看到“矩形贴片边界 / 重复图案 / 层和层各走各的”，而不是读到自然的云海空间。

参考 Wind Runners 后，更合适的方向是：

**低信息底层允许循环；有形状记忆的中近景不要全屏循环，而应改成稀疏的世界锚点、场景块、遮罩过渡和屏幕边缘速度参照。**

这和之前 Jet Lancer 文档不冲突。Jet Lancer 给出的原则是“背景退让、速度由战斗层和运动层承担”；Wind Runners 进一步补充了“近中景细节怎么不露循环”：它把大部分可识别细节放进舞台式 set piece，不把它当墙纸平铺。

## 3. Wind Runners 的背景组织方式

### 3.1 大面积底色很干净

视频里最常见的底层是高饱和天空、海面、沙漠、星空或平面色块。它们占画面面积很大，但信息密度低。玩家首先读到的是飞机、弹道、爆炸、敌人和 Boss，不会被背景纹理抢走。

对御剑原型的意义：

- 天空、海面、极远雾、超远山可以继续循环。
- 这些层必须是低频、低对比、低形状记忆。
- 如果一张贴图里有非常明显的山峰、岛屿、云洞、墨块，它就不应该作为全屏连续平铺层。

### 3.2 地平线和地景是稳定承托，不是满屏细节

Wind Runners 的海面、沙地、基地平台、山脚和远处地貌经常占据下半屏。它们的作用是让高速飞行发生在一个可理解的世界里，而不是让每一屏都有可识别装饰。

它的关键不是“地景很多”，而是：

- 地平线稳定。
- 下半屏有明确承托面。
- 中央战斗区保留大量空域。
- 地景细节主要在底部、远处或屏幕边缘。

对御剑原型的意义：

- 现在补海面和山脚雾的方向是对的。
- 中景岛群应贴住同一个海面锚点，不能山、岛、云、雾各自独立视差后互相滑开。
- 中央角色附近不应该出现清晰的矩形云块或山带边界。

### 3.3 有形状记忆的中景更像 set piece

视频里出现的巨型残骸、基地、沙漠山体、异星岩柱、巨大生物剪影，通常不是小贴片连续重复。它们像关卡段落里的大块舞台背景：进场、停留一段、离场。玩家记住的是“我飞过一个地方”，不是“同一张图又平铺了一次”。

对御剑原型的意义：

- 岛群、远处仙门、云中塔、悬浮山不应常驻平铺。
- 它们应该是世界坐标上的稀疏锚点，间隔足够长，并且有进出屏幕的淡入淡出。
- 同一个锚点内部如果需要补宽，不应默认 `tile_radius = 2` 连续铺 5 张；应优先单张、长条、局部遮罩或多变体拼段。

### 3.4 近景速度参照很克制

Wind Runners 的速度感主要来自飞机轨迹、导弹、弹道、爆炸碎片、目标相对运动和镜头，而不是让近景云和山不停高速滚动。近景层出现时通常位于底部、边缘或短时经过，给速度一个参照后就退场。

对御剑原型的意义：

- 近景云缕应该是高速状态的短参照，不是常驻前景纹理。
- 近景 atlas 要按实际 alpha 轮廓裁切，不能把整格半透明底画出来。
- Boost 时近景可以更长，但 alpha 应该低，且不要压过飞剑、敌弹、丝线和角色。

### 3.5 接缝被遮在低注意力区域

视频里的地面、水面、雾、屏幕底部、爆炸和运动残影经常构成天然遮罩。高对比动作发生在空域，背景接缝如果存在，也被压在低注意力区域或强运动区域。

对御剑原型的意义：

- 循环点不要放在角色水平线附近。
- 中景 / 近景循环如果不可避免，接缝应压到海平面雾带、底部云海、屏幕边缘或极低透明度层。
- 山脚海雾、海面水洗和云海前景不只是装饰，它们应该负责“焊住层级”。

## 4. 当前御剑背景的问题定位

当前脚本已经做了正确的第一步：

- `_draw_sky_wash()` 提供干净天幕。
- `_draw_sea_plane_wash()` 提供海平面承托。
- `_draw_world_island_groups()` 试图把岛、山、雾、云、地标锁到同一个世界锚点。
- `_draw_near_cloud_wisps_from_atlas()` 只在速度压力上来后画近景云缕。
- `_draw_battlefield_boundary_layers()` 把边界从 debug 框转向题材化云墙和符纹。

但穿帮的根因仍在三处：

### 4.1 锚点内部还在局部平铺太多张

`_draw_texture_anchored_tiled_x()` 默认 `tile_radius = 2`，这意味着一个岛群内部会横向画 5 张同一素材。素材只要不是严格无缝，或者透明边界有残留，就会在中景区域出现重复段。

Wind Runners 的做法更接近“一个大 set piece 从画面里经过”，而不是“一个中景块围着锚点左右铺满”。

### 4.2 atlas 单元格按整格绘制，透明底残留会变成矩形块

近景云缕按 `cell_size = texture_size * (0.5, 0.25)` 取整格绘制。如果源图 cell 的灰底抠图、alpha feather、边缘 bleed 不够干净，Godot 画出来的就是一个很淡但可见的矩形片。

这类问题降低透明度只能缓解，不能根治。正确方向是裁到实际 alpha bbox、扩边预乘、边缘羽化，并在运行时按内容 rect 而不是整格 rect 画。

### 4.3 中景层的图案记忆太强，循环后玩家能认出来

当前的山、岛、云海素材已经有比较明确的轮廓。它们放得少时能建立空间；一旦重复频率高，就会从“自然远景”变成“拼贴墙纸”。

玩家在高速移动中对这种重复很敏感，尤其是角色附近的水平带，因为眼睛会盯着角色和前进方向。

## 5. 与 Jet Lancer 文档的对比总结

| 维度 | Jet Lancer 旧结论 | Wind Runners 新补充 | 对 SwordCultivator 的合并结论 |
| --- | --- | --- | --- |
| 操控参考 | 不采用飞机狗斗操控 | 同样是 dogfight，不能直接搬操控 | 继续坚持直接御剑输入，不改成航向驾驶 |
| 背景职责 | 大面积低信息背景保护读性 | 中近景细节以场景块和地景承托出现 | 背景先服务读性，再服务空间身份 |
| 速度感来源 | 拖尾、弹道、镜头、目标运动为主 | 爆炸、残影、弹道和近景短参照共同支撑 | 速度线、飞剑尾迹、云气短线是主力，背景只辅助 |
| 循环策略 | 低频色块和远景可循环 | 有记忆点的中近景避免连续平铺 | 只有天幕、海面、极远雾、极低对比山带可做无感循环 |
| 细节摆放 | 背景不抢 Boss / 子弹 | 细节集中在底部、边缘、远处 set piece | 角色水平线附近要留白，穿帮层移出注意力中心 |
| 主题转译 | 不转现代飞机题材 | 不转科幻地景题材 | 只取层级方法，内容转成云海、远山、仙门、结界 |

一句话差异：

**Jet Lancer 告诉我们背景要退；Wind Runners 告诉我们中近景细节要“段落化”，不能当无缝墙纸用。**

## 6. 下一轮修正建议

### 6.1 先止血：中近景不再默认局部五连铺

对 `_draw_world_island_groups()` 中的非严格无缝素材，优先把 `_draw_texture_anchored_tiled_x(..., tile_radius)` 改成显式策略：

- 山体 / 岛链 / 地标：默认 `tile_radius = 0`。
- 海面水洗 / 山脚雾：可以 `tile_radius = 1`，但接缝要被低 alpha 和海面遮住。
- 中景云：优先单张或最多 `tile_radius = 1`，并压到海面 / 山脚附近，不放在角色同水平线。
- 只有经过平铺验收的极远底层，才允许全屏 `_draw_repeated_texture_tile_x()`。

验收：高速横飞时，角色附近不能出现周期性竖向矩形边界。

### 6.2 把近景云缕从“整格 atlas”改为“内容 bbox”

处理流程：

1. 离线扫描 `near_cloud_wisps_atlas_01.png` 的每个 cell，记录实际 alpha bbox。
2. 给 bbox 外扩 `4-8px`，并清理低 alpha 灰底。
3. 运行时按 bbox source rect 绘制，不画整格 cell。
4. Godot 导入检查 alpha bleed / premultiply，避免半透明灰底在缩放时露出。

验收：把近景云 alpha 临时拉高到 `0.2`，仍不能看到矩形 cell。

### 6.3 中景改成“世界段落”，而不是常驻带状贴图

建议新增一个轻量数据结构，替代单一重复层：

```gdscript
const BACKGROUND_SET_PIECES := [
	{"x": -14000.0, "kind": "far_island", "scale": 0.62, "depth": 0.34},
	{"x": -2400.0, "kind": "cloud_gate", "scale": 0.48, "depth": 0.30},
	{"x": 12200.0, "kind": "sword_peak", "scale": 0.56, "depth": 0.38},
	{"x": 28800.0, "kind": "mist_mountain", "scale": 0.70, "depth": 0.36}
]
```

每个段落只画自己需要的山、雾、岛、地标和局部云，不负责填满全屏。空白处交给天空、海面、远山底层。

验收：截图中每个地标像“经过一个地方”，不是“同一块素材又来了”。

### 6.4 接缝统一压到海面 / 雾 / 屏幕边缘

规则：

- 角色高度附近不要放高 alpha 接缝。
- 山脚、岛底、云海前缘必须被 `sea_mist_foot` 或代码雾带覆盖。
- 近景云缕尽量走屏幕边缘和下半屏，不穿过人物正后方。
- 需要循环的长条图，做一张 debug seam overlay，实机里按高速度横飞 30 秒检查。

验收：玩家说不出“这里在平铺”，只感觉空间在流动。

### 6.5 保留当前已经正确的方向

不要因为穿帮就推翻云海方案。当前值得保留的是：

- 天空和海面把战场从调试场拉到了云海大战场。
- 岛、山、雾、地标绑定到同一个海面锚点的方向是对的。
- 急转时降低背景保留比例的思路是对的。
- Debug guides 默认隐藏是对的。

要改的是中近景素材的使用方式：从“纹理循环”改为“舞台段落 + 遮罩焊接 + 低频底层”。

## 7. 推荐实施顺序

1. 文档确认：采用 Wind Runners 的中近景段落化原则。
2. 快速脚本止血：把岛群内部的中景山 / 岛链 / 中景云 `tile_radius` 降到 `0` 或 `1`，先看穿帮是否消失。
3. 近景云 atlas 修复：生成 bbox manifest，运行时按 bbox 绘制。
4. 设置一个“背景 seam 压力测试”：高速横飞、Boost、急转各录 20-30 秒。
5. 如果空间变空，再补新的 set piece，而不是把旧素材重新铺满。
6. 稳定后再抽 `YujianBattlefieldBackground2D`，当前阶段先别为了架构拆分增加调试成本。

## 8. 一句话验收标准

成功版本应该让玩家感觉：

**我在云海大战场里经过远山、岛群和雾带，但我看不到任何背景贴片在循环。**
