# 战斗框架槽位拆解 V1（肉鸽构筑基础）

> 状态：草案，待原型验证
> 日期：2026-10-03
> 依据：web 原型 `tools/web_demo/yujian_combat_proto.html`（边飞边打）的现有战斗框架；`docs/decisions/PROJECT_DECISIONS.md` 第 16 条“锻造词条与动态战斗适配原则”

---

## 0. 这份文档要解决什么

当前边飞边打的战斗框架已经验证可玩。下一步要做肉鸽构筑，以及多种性格的剑修，但不能推倒重来，而是：

1. 把现有框架**拆成若干槽位**，写清楚每个槽位在战斗里负责什么；
2. 每个槽位定义**可替换的形态模块**（例如剑阵换形状、御剑一剑分三）；
3. 在槽位之上叠一层**剑修**（本命槽 + 身法 + 道心），让“换一位剑修”和“换一套构筑”两种变化同时成立。

结构定位：

```
剑修（性格）  = 本命槽（锁定的招牌形态） + 身法手感 + 道心（模块池倾向 + 剧情）
局内构筑（变化）= 其余槽位在一局中拾取、替换的形态模块
战斗框架（底座）= 本文拆出的 5 个槽位与它们之间的联动事件
```

先做**单角色槽位构筑**，验证“换模块 = 换解法”成立；再把验证过的强烈差异固化成剑修的本命。

---

## 1. 设计原则

1. **职责固定，解法可变。** 每个槽位守住自己的战斗职责；模块只能改变完成这些职责的方式（身体结构、空间形态、节奏、承诺感），不能替换或废掉这些职责。
2. **模块改变形态，不改数值。** 一个模块如果只能用“+X% 伤害 / 射程 / 冷却”来描述，就不合格。每个模块都必须回答：*它让哪一类战斗问题换了一种解法？*
3. **所见即所想。** 模块的效果必须看得见、读得懂，不能有隐藏的数值补偿或橡皮筋。敌人的规则同样如此，比如敌人速度是固有属性，不随玩家状态变化。
4. **不加新按键。** 所有模块都挂在现有输入上：鼠标转向、左键、右键、空格、W/S。
5. **保护签名体验。** 御剑时停与居合兑现、回锋斩的掉头一斩、险（极限闪避），这些是项目的签名时刻。模块可以改变它们的形态，但不能拿掉它们。
6. **敌人的克制规则属于敌人。** 墨甲卫正面弹开非御剑攻击、蓄势针站在剑阵射程之外，这些是关卡出的“题”。模块可以提供另一种解法（比如更容易绕背），但不能直接取消克制。

## 2. 战斗问题清单

槽位职责要用“玩家在战场上要解决的问题”来定义。目前原型里的问题有：

| 编号 | 战斗问题 | 现在由谁出题 |
|---|---|---|
| P1 | 接近 / 追上目标 | 墨鸦横移走射、敌人速度固有，慢的追不上你，快的甩不掉 |
| P2 | 规避弹幕与突进 | 墨鸦预判弹、扇傀扇形弹、穿云锥冲刺、墨甲卫盾推、蓄势针重针 |
| P3 | 近身兑现（把靠近转化成击杀） | 所有普通敌人 |
| P4 | 处理弹幕本身（斩弹、挡弹） | 扇傀弹幕墙 |
| P5 | 群体压制（同时处理多个目标） | 成群刷怪（每队 3–5 只） |
| P6 | 精英 / 有防御的目标 | 墨甲卫（正面墨甲，要绕背或用御剑） |
| P7 | 远程高价值目标 | 蓄势针（站在剑阵射程外，约 32 米） |
| P8 | 机制处理 | 千丝傀儡师：闭窗时刀剑不入，要用御剑切断丝线 |

## 4. 各槽位详解

每个槽位都按同样的结构展开：现状 → 底线（模块不可改）→ 可变维度（模块接口）→ 候选模块。候选模块只是样例，用来检验接口是否合理，不代表最终内容。

### 4.1 A 身法

**现状**

- 战场里永远在飞，没有悬停。鼠标控制转向（剑尖以有限转速追向鼠标方向）。鼠标放在身边时进入缓飞，速度约为巡航的 40%。
- W/S 是油门档位，范围从缓飞到催剑上限。默认速度下，巡航约 15，加速约 29。
- 空格：破空闪避，沿剑尖向前闪，带位移、残影、无敌帧，冷却约 0.9 秒。表现可以切换成“流线回环”或“身化剑光”。
- 险：在无敌帧内擦过子弹或撞到敌人，会触发险，奖励剑意并短暂慢放。破空无敌帧内穿过敌人时，顺手砍它一剑（“穿身”）。

**底线（模块不可改）**

- 永远在飞，鼠标转向，飞行方向就是攻击方向。
- 空格必须是一个能保命的规避动作（P2），而且必须有可读的无敌窗口。
- 险的判定与奖励保留，它是签名时刻。

**可变维度**

- 破空的**形态**：位移轨迹、残影会做什么、闪避结束时会发生什么。
- 破空**与其他槽位的联动**：比如险触发什么。
- 注意：转向、惯性、速度档位这些**身法手感参数，留给剑修层**，不作为局内模块，否则剑修的性格会被构筑冲淡。

**候选模块**

| 模块 | 玩家感受 | 改变了哪个问题的解法 |
|---|---|---|
| **残影补刀** | 破空留下的残影在 0.3 秒后沿原轨迹再斩一次 | P2 变成进攻：闪过去，残影替你补刀 |
| **惊鸿** | 险之后的 1.5 秒内，速度不回落，并且下一次顺锋斩视为冲锋斩 | 把险变成追击和兑现的起点（P1 → P3） |
| **折锋** | 破空方向改成沿鼠标方向，而不是剑尖方向，但距离缩短 | 用于急转规避，代价是位移变短；适合缠斗型打法 |

### 4.2 B 近身剑

**现状**

- **顺锋斩**：左键点按。扇形斩击，半径约 4.2 米、半角约 75°，1 点伤害，命中后派 2 把阵剑。
- **冲锋斩**：速度高于巡航时，顺锋斩会自动放大（倍率 `chargeMul`），伤害变成 2 点。
- **回锋斩**：高速掉头超过约 110° 后的 0.5 秒内按左键（掉头前 0.14 秒内先按也算）。整圈大斩，半径约 5.6 米，2 点伤害，出手时派 6 把阵剑。
- **斩弹**：斩击扇面略宽于伤害判定，扫到的敌方子弹会被反弹（打回去造成伤害）。
- 出剑吸附：剑尖 ±40°、7 米内有敌人时，剑弧会自动偏向它。

**底线**

- 左键是近身兑现，也就是 P3。
- 斩击要能处理子弹（P4），可以反弹、挡下或击碎，但不能变成对子弹完全无能为力。
- 回锋斩的触发方式（高速掉头 + 左键）不变，它是飞行与攻击的签名结合点。

**可变维度**

- 斩击的**空间形态**：长 / 短、宽 / 窄、是否穿透、是否留下持续区域。
- 斩弹的**处理方式**：反弹、吸收、击碎并转化。
- 冲锋斩和回锋斩的**附加形态**。

**候选模块**（与第 16 条里的 `长锋 / 阔刃` 等词条方向对齐）

| 模块 | 玩家感受 | 改变了哪个问题的解法 |
|---|---|---|
| **长锋** | 斩击变成又长又窄的一线，射程约 7 米、半角约 25° | P3：不用贴身，在远一点的地方点杀；代价是要瞄得准 |
| **阔刃** | 斩击变成短而宽的近半圆 | P4 / P5：贴身横扫，一刀清掉身边的子弹和小怪 |
| **穿锋** | 冲锋斩会从敌人身上穿透，向前甩出一道剑气 | P3：高速下一刀砍不死时不用掉头，剑气会补完；奖励一路冲到底 |
| **墨旋** | 回锋斩在原地留下一团约 1.5 秒的墨旋，持续切割并吸附子弹 | P4 / P5：掉头的同时留下一个阵地，适合被追尾的时候 |

### 4.3 C 御剑

**现状**

- 右键**点按 = 点刺**：主剑飞向准星，直线刺穿，消耗 10 剑意。
- 右键**长按 = 连斩**：主剑跟着准星在场中划切，没有速度上限，也没有活动半径限制。起手消耗 10 剑意，之后每秒 20。
- 御剑期间：锁定航向，全场连同自己一起停止（慢放倍率默认 0），画面水墨化。
- 居合：普通敌人一刀必杀，精英每刀 4 点。切中时剑顿一下、敌人震动、朱砂刀痕；致命的一刀让敌人当场裂成两半悬停，收剑时统一炸散。必须先划出再划入，才算新的一刀。
- 收剑时派 12 把阵剑。御剑无视墨甲，能切断丝线。

**底线**

- 御剑必须能完成 P6（无视墨甲或者等价的破防）和 P8（切丝）。
- 时停 + 居合兑现的节奏是签名体验：**出剑（世界静止）→ 划切 → 收剑（统一兑现）** 这个三段结构不能拆。
- 消耗剑意，所见即所想：没有隐藏的冷却和隐藏的限制。

**可变维度**

- 飞剑的**数量与组织方式**：一把、分光、分身。
- 划切的**轨迹规则**：直线、折返、留驻。
- 兑现时的**形态**：炸散、牵连、留下效果。

**候选模块**

| 模块 | 玩家感受 | 改变了哪个问题的解法 |
|---|---|---|
| **一剑分三** | 点刺时分成三道扇形；连斩时三把剑并排跟随准星（中间那把是主剑） | P5：时停里一笔切一大片；代价是每把剑都更难对准单个目标 |
| **回环剑** | 点刺到底后自动折返，回程再切一次 | P6：精英前后各切一刀；同一笔划可以兑现两次 |
| **留剑** | 收剑时主剑不回手，钉在最后的位置几秒，周围的敌人被定住 | P7 / P8：把主剑当成远处的“钉子”，代价是这几秒手里没剑，顺锋斩变弱 |
| **牵丝** | 居合兑现时，同一笔划切中的敌人互相连线，一起炸散，炸散波及周围 | P5：鼓励一笔串起多个目标 |

### 4.4 D 剑阵

**现状**

- 12 把阵剑，平时待命，在动作触发模式下不显示。
- 派剑由动作触发：顺锋斩命中派 2 把，回锋斩出手派 6 把，御剑收剑派 12 把。
- 阵剑追击射程（默认 12 米）内的敌人，由近到远轮流分配；不会绕过墨甲，打不碎蓄势针的重针，默认也不击碎子弹。阵剑射出后飞回待命。
- 另外还有全自动、手动（E 键）两种模式，目前作为备选。

**底线**

- 剑阵负责 P5 群体压制，必须是**持续可见的飞剑层**，不能退化成隐形的被动伤害。
- 派剑由动作触发，这条联动不变：剑阵是对玩家动作的回应，不独立开火。
- 遵守定案里的剑阵原则：不加按键、不用滚轮切阵、不由系统自动判断阵型；扇阵不作为独立阵型恢复。

**可变维度**（也就是你说的“剑阵替换形状”）

- 阵剑的**组织形状**：散射追击、环绕、直线贯穿、合一。
- 阵剑的**命中方式**：一次性、回旋多次、驻留。
- 阵剑**对子弹的态度**：无视、挡下、击碎。

**候选模块**

| 模块 | 玩家感受 | 改变了哪个问题的解法 |
|---|---|---|
| **散星（默认）** | 现在的行为：派出的剑各自追向射程内最近的敌人 | P5 基线 |
| **环阵** | 派出的剑不追敌，绕身旋转数秒，切割靠近的敌人、挡下子弹 | P2 / P4：把攻击变成护体，适合冲进怪群 |
| **贯穿阵** | 派出的剑沿剑尖方向排成一线射出，射程更远，可以穿透 | P7：剑阵也能“点”远处的蓄势针；代价是不再自动分配目标 |
| **合一** | 派出的剑在身前合成一把巨剑，数量越多越大，再一次性贯出 | P6：攒剑打出一记重击；适合回锋斩、收剑这类大量派剑的时刻 |

“环阵 / 贯穿阵”和定案里的两类职责（近身护体、远距破线）对应。在肉鸽里，它们从“手动切换的阵型”变成了“局内拾取的形态模块”，所以不违反“不加按键、不自动判断”这些原则。

### 4.5 E 剑意（资源与道心）

**现状**

- 获取：任何来源的击杀、斩弹，各 +10（滑条 `killEnergy`）；近身命中（顺锋 / 回锋 / 斩弹反击 / 穿身）+4，击杀时另加击杀剑意；险 +`riskEnergy`。
- 消耗：御剑（点刺 10，连斩起手 10 + 每秒 20）。

**定位**

剑意不是一个“攻击槽”，而是把 A–D 串起来的循环。它的模块不直接放在局内三选一里，而是**主要由剑修的道心决定**：

- 道心改的是**剑意从哪来**，也就是在鼓励哪种行为。不改单纯的倍率。
- 例：重剑道心，命中未杀的剑意多一些，奖励重击；飘逸道心，险的剑意多、斩弹的剑意少，奖励擦弹；剑阵道心，阵剑击杀额外返还剑意。

## 5. 联动事件表

目前槽位之间是靠事件联动的。模块化之后，**每个模块都只能通过这些事件和其他槽位通信**，不能直接改其他槽位的内部状态。这样任意两个模块组合在一起时，行为都可以预期。

| 事件 | 由谁产生 | 现在谁在监听 | 用途 |
|---|---|---|---|
| `slash_hit`（顺锋命中，每刀一次） | B | D 派 2 剑 | 近身兑现时剑阵跟上 |
| `carve_start`（回锋出手） | B | D 派 6 剑 | 掉头时剑阵爆发 |
| `sheathe`（御剑收剑） | C | D 派 12 剑 | 居合之后剑阵收尾 |
| `kill` / `deflect` | B、C、D | E +剑意 | 资源循环 |
| `close_hit`（近身命中） | A、B | E +4 | 奖励贴身 |
| `risk`（险） | A | E +剑意，全局慢放 | 签名时刻 |
| `dash_through`（破空穿身） | A | 造成伤害 | 闪避也是攻击 |

模块可以**监听**事件，比如惊鸿监听 `risk`；也可以**产生**新的事件，比如残影补刀产生 `slash_hit`。产生事件时要标明来源，防止连锁触发失控：例如残影的 `slash_hit` 不再派剑，或者派剑减半。

## 6. 模块规范

### 6.1 模块卡模板

每个新模块都要先填这张卡，再进原型：

```
名称：
槽位：A 身法 / B 近身剑 / C 御剑 / D 剑阵
一句话手感：（玩家会怎么描述它）
改变的解法：（哪个战斗问题 P1–P8，原来怎么解，现在怎么解）
守住的底线：（这个槽位的哪些职责仍然成立）
代价 / 取舍：（变强的同时失去了什么；没有代价的模块会变成必选）
可读性：（玩家第一次拿到时，靠什么看懂它）
监听 / 产生的事件：
验证方法：（在哪一波、对哪种敌人，最能看出差异）
```

### 6.2 允许改 / 禁止改

| 允许 | 禁止 |
|---|---|
| 攻击的空间形状、数量、轨迹、驻留时间 | 新增按键或输入方式 |
| 对子弹的处理方式 | 让某个槽位的主要职责失守（第 3 节覆盖矩阵） |
| 监听或产生联动事件 | 直接改其他槽位的内部状态 |
| 换一种代价（距离、准度、时机、剑意） | 只加数值而没有形态变化 |
| 提供绕开敌人克制的另一种解法 | 直接取消敌人的克制规则 |
| — | 隐藏效果、隐藏冷却（违反所见即所想） |

### 6.3 同槽位的强化

同一个模块在一局中再次拿到时，要**加深形态**，而不是加数值。例如一剑分三 → 一剑分五；环阵 → 环阵加上反弹子弹。具体怎么设计，留到构筑流程阶段再定。

## 7. 剑修层（初步）

剑修建立在槽位框架之上，由三样东西组成：

- **本命槽**：锁定一个槽位的招牌形态，局内不可替换。
- **身法手感**：转向速度、惯性、速度档位、破空形态。这是性格最直接的来源，成本主要在调参数和动画风格。
- **道心**：剑意的来源偏向（4.5 节）、局内模块池的权重（偏向但不禁止），以及剧情线。

初步映射（只是方向，不是定稿）：

| 剑修 | 本命槽 | 身法手感 | 道心（剑意偏向） |
|---|---|---|---|
| 重剑·力量 | B 近身剑：重斩（蓄势一刀，劈开弹幕） | 转向慢、惯性大、冲撞有分量 | 命中未杀、击破精英 |
| 飘逸 | A 身法：一种专属的破空形态 | 转向灵、速度高 | 险、擦弹 |
| 剑阵 | D 剑阵：专属的阵型 | 偏慢、重站位 | 阵剑击杀 |
| 近战·快剑 | B 近身剑：连击 / 弹反 | 中速、急停急转 | 斩弹、连击 |
| 御剑 / 居合（备选） | C 御剑：专属的居合形态 | 平稳 | 居合兑现 |

延伸设想：每一位剑修既是可玩角色，也是别的剑修历劫路上的“问剑”对手。一套动作资产同时撑起可玩角色和 Boss 两份内容。

### 第一步：代码层槽位化（不改手感）——已完成（2026-10-03）

**实现情况**（`tools/web_demo/yujian_combat_proto.html`，搜索“战斗框架槽位”）：

- 五个槽位 `move / blade / sword / array / qi`，各装一个默认模块 `basic`，对应现有行为：破空、顺锋、单剑、散星、剑意。
- 模块接口：
  - 身法 `dodge() / step(dt, pc, h)`。险的判定、无敌帧、穿身属于底线，留在核心。

- 随机数拆成两路：`rand` 只给玩法（刷怪、AI），`vrand` 只给视觉（粒子、云、风线、水花）。这样视觉状态不再影响玩法随机序列，以后做“固定种子的一局”也能直接用。

### 顺带修正：入场敌人吊在画面外

验证第四步时发现：从身后刷出的墨鸦，会以玩家巡航速度吊在 18 米外，始终飞不进画面。原因是“敌人速度固有化”之后，追击速度随距离递增，墨鸦在 18 米处刚好和巡航速度持平。这会让关卡永远清不完。

修正：**还没飞进画面的敌人，按自己的最高速度径直朝玩家飞**。这仍然是固有速度，没有按玩家速度补偿：

- 墨鸦（18）比巡航（约 15）快，会追进画面。
- 比巡航慢的敌人追不上，玩家一直飞就把它甩掉，落后 70 米后消失。
- “穿云锥夹击”的穿云锥比巡航慢，所以改为从前方两侧刷出。

这是一次有意的默认玩法改动，回归基准已重新记录。

### 第五步：剑修原型（重剑 vs 飘逸）——已完成，待真人试玩

试玩第二至四步后，用户的反馈是：“形态的改变让游戏变得有趣多了”。但真正让人换了打法的只有剑阵的两个模块（环阵、贯穿阵）。原因是这两个模块改变了**人该在哪里、剑尖该朝哪**；其余模块只是在原来的动作上自动多加一层效果。

由此得出剑修设计的原则：**剑修的性格 = 它逼出的行为模式**，而不是属性差。

**实现**（搜索“剑修（docs/systems”）：

- 剑修 = 身法手感（`BODY` 倍率：转向、加速、速度档位、破空距离、无敌帧）+ 本命槽（锁定的招牌模块，局内三选一不会出现、面板也不能改）+ 道心（剑意来源，锁在剑意槽）。
- 选择入口有两处：标题画面“历劫”先“择道”选剑修；面板“构筑”顶部的“剑修”下拉框（用于对比试题）。

| | 重剑 · 开山 | 飘逸 · 惊鸿 |
|---|---|---|
| 一句话 | 一剑开山，迎着刀口上 | 衣不沾尘，穿弹而过 |
| 身法 | 转向 ×0.6、加速 ×0.75、速度 ×0.92、破空距离 ×0.6 | 转向 ×1.55、加速 ×1.3、速度 ×1.12、破空距离 ×1.15、无敌 ×1.35，破空冷却 0.45 秒 |
| 本命 | **开山**（近身剑）：点按是顺锋斩；按住蓄势，正面挡下一切子弹（含重针），但身形放缓、几乎转不动；松开劈出开山斩，蓄得越久越远越重，蓄满破甲 | **惊鸿**（身法）：触发「险」后 1.5 秒内（身上金环），左键瞬身斩过前方最近的敌人，3 点伤害 |
| 道心 | 贴身命中 +6，横剑挡弹每颗 +3，险减半 | 险双倍，贴身命中 +2，斩弹六折 |
| 逼出的行为 | 迎着弹幕蓄势、硬顶着冲进去劈开 | 主动去擦弹，用险换瞬斩 |
| 弱点 | 巡航慢，墨鸦追得上；蓄势时侧面、背后是空门 | 伤害轻、不破甲；不擦弹就没有瞬斩 |

**脚本验证**：

- 身法：巡航 / 掉头 180° 用时 / 催剑最高，三者对比：
  - 默认：14.9 / 0.63 秒 / 29.0
  - 重剑：13.7 / 1.03 秒 / 26.6
  - 飘逸：16.6 / 0.40 秒 / 32.4
- 开山：
  - 蓄势时正面打来 8 颗子弹（含 2 颗重针），全部挡下，不受伤；蓄势中速度降到 7.5。
  - 蓄满正面劈墨甲卫：8 → 4 血（破甲）；蓄一半被墨甲弹开，但两侧 3 血墨鸦全灭；点按就是普通顺锋斩。
- 惊鸿：险后左键瞬移 14 米，斩杀前方 3 血墨鸦；没有险时左键只是普通出剑。
- 历劫（选重剑）：五次三选一都没有出现近身剑模块（本命槽锁定），面板近身剑下拉框变灰，结算表记录剑修和最终构筑。
- 默认玩法（自由构筑）不受影响：回归测试与加入剑修前逐帧一致。
- 原来的身法模块“惊鸿”（险后锁定最快剑速）改名为**乘势**，避免和飘逸本命同名。

**真人试玩方法**：

- 用两位剑修各打同一道对比试题，以及各打一局历劫。
- 看两局的飞行路线和出手时机是否完全不同：重剑应该是迎面蓄势、直线冲进去；飘逸应该是贴着弹幕绕、擦弹后瞬斩。
- 不成立的信号：两位剑修打同一道题的方式差不多，只是“快一点 / 慢一点”。

**回归测试的可靠性**（这一轮修正）：之前的测试有三个隐藏的不确定来源，现在都已处理。

1. **角色模型异步加载**：现在等 `state.modelState` 不是 `loading` 再跑。
2. **悬停起伏动画按全局模拟时钟 `simTime` 走**：现在测试开始时用 `setSimTime` 固定。
3. **同一页面重复运行会残留状态**：现在同一页面跑第二次会直接报错，要求先刷新。

修正后，不同等待时间、连续多次页面加载，结果都逐帧一致。但还剩一个已知问题：浏览器空闲一段时间后第一次加载，偶尔会走另一条轨迹，原因未查明。加入剑修前后的代码在同样条件下都会出现这条轨迹，所以不影响“默认玩法不变”的结论。遇到不一致时刷新页面再跑一次，连续两次一致才算结果。基准哈希记在测试文件开头。
