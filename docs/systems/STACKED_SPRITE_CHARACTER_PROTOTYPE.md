# 堆叠精灵人物技术方案

- 日期：`2026-05-24`
- 范围：研究“堆叠精灵人物”在《SwordCultivator》御剑角色上的可用性
- 原型入口：`res://scenes/prototypes/YujianStackedSpriteCharacterPrototype.tscn`
- 原型脚本：`res://scripts/prototypes/yujian_stacked_sprite_character_prototype.gd`
- 当前角色参考：`res://resources/modle/000_男主角/000_Nanzhujue_LOD.FBX`

## 1. 目标

这个技术不是为了把角色做成完整 3D，也不是给现有序列帧简单叠几层阴影。它的价值在于：保留像素/手绘角色的可控轮廓，同时让人物在御剑飞行时有可读的厚度、压身、转向和上升/下潜体感。

玩家侧要读到三件事：

- 剑首方向和身体重心明确，不能因为层片厚度糊掉朝向
- 御剑时人是“站在有空间厚度的剑上”，不是贴在屏幕上的纸片
- 高速回锋、压剑、侧身时，身体和衣摆能给出立体姿态，而不是只靠拖尾补速度感

## 2. 技术结论

真正可用的堆叠精灵人物应当使用“切片资产”，而不是复制整张角色图：

- 每个动作帧拆成多层横截面切片
- 每层有统一 pivot，pivot 锁在“脚踩剑/剑身中心”锚点
- 运行时所有层共享同一个动作帧号
- 层片按伪高度 `z` 投影到屏幕，并按 `z_index` 排序
- 转向、爬升、下潜、回锋只改变层片投影方向和压缩比例，不改变移动控制

复制整张角色图可以做“厚阴影验证”，但它会把轮廓变脏，不能作为正式美术路线。

## 3. 资产规格

建议第一版资产只做一个动作：御剑巡航 idle。

- 动作：`idle_cruise`
- 帧数：`8` 或 `16`
- 切片层数：`16..24`
- 单层尺寸：建议 `192x128` 或 `256x160`
- 背景：透明 alpha
- 锚点：每一层相同，位于剑身中线和双脚落点附近
- 命名：`stacked_yujian_idle_f00_z00.png` 这类 frame/z 双索引格式
- 图集：后续可合成 `frames x layers` 的二维 atlas，运行时用 `frame_index` 和 `layer_index` 取 region

层片语义建议从下到上：

- `z00..z03`：飞剑、脚底、衣摆底部、近地阴影
- `z04..z08`：下摆、腰胯、外袍主体
- `z09..z13`：胸口、袖子、手臂、剑诀姿态
- `z14..z18`：脖颈、头、发冠、发束
- `z19+`：飘带、发梢、袖尖、可选剑气光边

## 4. 运行时结构

建议最终节点结构：

```text
YujianStackedCharacterRoot (Node2D)
  LayerRoot (Node2D)
    Slice_00 (Sprite2D)
    Slice_01 (Sprite2D)
    ...
    Slice_23 (Sprite2D)
  TrailAnchor (Marker2D)
  FootAnchor (Marker2D)
```

每层运行时需要的数据：

- `height_z`：层片高度，`0..1`
- `frame_region`：当前动作帧的 atlas 区域
- `local_offset`：美术校正偏移
- `depth_width`：层片本身的横向厚度读法
- `occlusion_bias`：处理袖子、头发等前后遮挡时的排序偏移

投影公式保持简单：

```gdscript
slice.position = base_offset + local_offset + stack_axis * height_z
slice.z_index = base_z + layer_index + occlusion_bias
slice.scale.y = pose_squash
```

其中 `stack_axis` 由镜头角、航向、上升/下潜和回锋压力共同决定。

## 5. 动作系统边界

堆叠精灵人物只负责表现，不负责移动：

- 不改变 `target_heading`
- 不改变 `body_heading`
- 不改变速度、刹车、回锋轨迹
- 不抢 clip graph 的状态判断
- 不在输入层制造新的语义

它应该接收这些已经存在的表现参数：

- 当前动作帧号
- 朝向符号
- 身体航向
- 速度强度
- 爬升/下潜强度
- 转向/回锋强度

## 6. 当前原型

当前新原型先不生成正式手绘资产，而是从当前男主 3D 模型的 SubViewport 渲染结果里切水平层片：

- 左侧显示当前男主 3D 模型参考
- 右侧使用同一份模型渲染图，按高度切成多条 `Sprite2D` 层片
- 每条层片保持原模型贴图、轮廓和颜色，只在运行时做轻微错层、摆动、压缩和排序
- 这不是最终资产方案，但可以先验证“从同源角色生成的堆叠读法”是否成立

这版原型的关键是避免凭空画一个新角色。它必须先和现有男主长得像，再讨论堆叠精灵是否足够立体。

这个原型的意义是验证：

- 模型水平切片能不能形成足够稳定的御剑人物体积
- 角色识别是否和现有男主同源
- 上升/下潜、侧身、回锋时层片是否会糊成一团
- 是否值得进入正式切片资产制作

## 7. 验收标准

通过标准：

- 静止时能读出“男主站在剑上”的纵向体积
- 旋转/摆动时能读出头、躯干、衣摆和剑的相对空间
- 黑发、浅衣、深袍、飞剑四个角色识别点稳定
- 层片错位不会遮住脸、手、剑首方向
- 关掉 3D 参考后，堆叠人物仍能独立成立

不通过标准：

- 看起来只是整张图拖影
- 层片太厚导致角色变成一团色块
- 剑和脚锚点漂移，破坏“踩剑”可信度
- 高速或转向时朝向读不出来

## 8. 后续制作路线

推荐下一步路线：

1. 用当前原型调定层数、投影轴、角色高度和屏幕尺寸
2. 让美术先画 1 帧正式堆叠切片，不做动画
3. 在同一原型里替换模型水平切片，验证正式手绘切片是否比模型切片更清晰
4. 再扩展到 `8` 或 `16` 帧巡航 idle
5. 最后才接入现有御剑飞行 clip graph

这条路线比一开始做全套动作更稳，因为堆叠精灵的第一风险不是帧数不够，而是角色层片一动就丢失身体重心和剑身锚点。
