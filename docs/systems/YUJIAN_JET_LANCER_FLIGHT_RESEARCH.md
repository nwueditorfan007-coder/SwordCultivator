# Jet Lancer 御剑飞行调研与否决记录

- 日期：`2026-05-23`
- 状态：已否决方向记录
- 结论：不要采用 Jet Lancer Arcade Type 式御剑飞行操控
- 范围：记录设计判断，避免后续再次实现同类操作方案

## 1. 结论

本项目不采用 Jet Lancer Arcade Type 的飞行操控方式。

已否决的具体方案包括：

- `A / D` 持续旋转角色或剑首航向。
- `W` 作为沿当前航向持续推进的油门 / 催剑键。
- 松开 `W` 通过失速、滑行、收势来缩小转弯半径。
- `S` 作为刹势 / 急收，用于压弯和回身。
- `Shift` 作为航向推进体系里的 afterburner / 破空加速。
- `Space` 作为 Jet Lancer 式 roll / dodge 的翻锋闪避。
- 攻击方向默认绑定当前航向，而不是当前项目已有的御剑 / 战斗指向逻辑。

这类操作不应再次作为默认方案、原型方案或主战斗接入方案提出。

## 2. 为什么否决

### 2.1 玩家不想要这种身体负担

试验后的直接反馈是：不要这种操作方式。

这种方案把玩家的主要负担放在“转航向、控油门、松油门回身、刹车压弯”上。它适合 Jet Lancer 式飞机狗斗，但并不符合当前想要的御剑操作感。

它让玩家感觉像在驾驶一架二维飞机，而不是在一个剑修动作系统里使用御剑能力。

### 2.2 它会把御剑推向另一个游戏类型

当前项目核心仍是：

- 近战建立节奏、弹反与资源。
- 右键御剑处理关键目标、切机制、制造窗口。
- 剑阵作为可见飞剑形态层，在强化窗口内兑现近中远职责。
- Boss / Puppet / Silk 围绕机制处理和开窗输出。

Arcade Type 飞行会把重心改成：

- 航向管理。
- 大地图狗斗。
- 追逐、过冲、回身、咬尾。
- 以飞行轨迹作为主要攻击语法。

这会稀释当前已经成立的主战斗结构，也容易把御剑从“我亲自处理关键点”变成“我在开一套飞行载具”。

### 2.3 它会和现有输入职责冲突

当前项目已经有清晰的输入身份：

- `WASD`：主战斗平面走位。
- 鼠标：近战朝向、御剑目标、剑阵意图。
- 右键：御剑点刺 / 连斩。
- `Space`：后续定案中的强化剑技入口。

Arcade Type 会要求：

- `A / D` 不再平移，而是旋转航向。
- `W` 不再上移，而是油门。
- `S` 不再下移，而是刹车。
- `Space` 变成翻滚 / 闪避。

这会破坏当前主战斗肌肉记忆，也会抢占 `Space` 强化剑技职责。

### 2.4 视觉和动画也不天然支持

当前 2D 序列帧可以表现低速巡航、高速巡航、低速转身和高速急转，但它不是完整的自由航向飞行系统。

如果底层做完整航向，却只用左右镜像表现角色，会出现“移动方向、剑首方向、人物姿态”三者不一致的问题。若直接旋转整套序列帧，又会破坏已有帧匹配、转身 clip 和拖尾锚点。

这类成本不应继续投入，除非未来明确要做一个独立飞行游戏模式。

## 3. 可保留的 Jet Lancer 参考

Jet Lancer 仍可以作为表现参考，但只取飞行姿态、动画组织和速度读感，不取操控结构。

可以参考：

- 飞行姿态：高速时身体前压、重心收紧，低速或回身时姿态有明显收势。
- 动画表现：加速、急转、闪避、回身都应有清晰的起势、持续和收势，而不是只改速度数值。
- 转向表现：急转可以参考 Jet Lancer 的重量感、拖尾弧线、残影和短承诺读感，但不能要求玩家使用同样的航向驾驶输入。
- 速度读感：高速动作需要拖尾、残影、镜头、背景运动和敌人压力共同支撑。
- 高速感需要敌人、镜头、目标和弹幕共同支撑。
- 加速、闪避、回身等动作都应该有明确读感和节奏窗口。
- 大战场目标不能只是把地图放大，需要追击、穿越、拦截、保护或机制目标。

不要参考：

- Jet Lancer Arcade Type 的航向旋转输入。
- 油门 / 松油门 / 失速回身作为核心操作。
- 把攻击方向默认绑定航向。
- 把御剑做成二维飞机狗斗。

## 4. 后续御剑飞行设计边界

后续如果继续做御剑飞行，应先重新定义玩家想要的身体感，而不是沿用 Jet Lancer Arcade Type。

当前边界：

- 不采用 `A / D` 旋转航向的驾驶式操作。
- 不采用 `W` 油门式推进。
- 不采用松油门失速回身作为核心技巧。
- 不把 `Space` 改成飞行翻滚闪避。
- 不把主战斗 `WASD` 肌肉记忆替换成飞行驾驶语法。
- 不把当前右键御剑切机制和剑阵连续变形让位给飞行狗斗。

更合适的后续探索方向应从“御剑题材的动作感”重新出发，例如：

- 保留更直接、可信、低负担的移动控制。
- 让动画适配操作，而不是让玩家为动画状态机付出驾驶负担。
- 可以参考 Jet Lancer 的飞行姿态、急转姿态、加速拖尾、残影、镜头速度感和闪避动画读法。
- 优先解决当前“动画和操作不匹配”的问题，而不是引入完整飞行狗斗模型。
- 若需要高速段，做成短时动作或关卡片段，而不是整套主操作方式。
