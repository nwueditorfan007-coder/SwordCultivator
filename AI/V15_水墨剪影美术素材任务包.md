# Sword Cultivator V15 水墨剪影美术素材任务包

## 0. 任务定位

V15 不是在 V13/V14 的写实仙侠骑乘者上继续加细节，而是重定一条更清楚、更可组合的视觉路线：

- 角色是黑影小人，轮廓优先，不强调脸、衣纹、复杂材质。
- 场景是水墨空域，像纸面、云山、墨雾和高速风场叠出来的战场。
- 战场布局参考 Jet Lancer 的高速 2D 空战读屏方式：横向空域、稳定战斗视窗、远近层强烈视差、敌方威胁从画面边缘和远端进入。
- 操作表达仍服务 Sword Cultivator：右键御剑、剑阵释放、连续剑阵形变、高速移动、高速转向必须同时清楚。

本包是给美术、AI 生图、切图和实现接入使用的生产任务书。

## 0.1 接入路线定案

V15 固定采用以下路线，不再在生产中二选一：

```text
常驻角色：V14 rig schema 的水墨剪影替换版
短强动作：独立 FrameOverlay 横向 strip，盖在 rig 之上
背景场景：分层 Parallax/自定义滚动层
VFX：独立 PNG + shader/程序控制 alpha、速度和转向
```

含义：

- V15 rig 必须沿用 V14 的部件命名和 manifest/pose library 数据结构，降低接入成本。
- `FlightRiderBodyRigFx` 后续需要把 V14 路径参数化，或临时切换到 V15 路径。
- 序列帧不混入 `flight_rider_body_v13_1_sheet.png` 的 16 帧行式 atlas；V15 短强动作统一作为 `FrameOverlay` 交付。
- 骨骼/部件 rig 始终在后台更新 root、朝向、速度、手部意图；FrameOverlay 只负责释放、转阵、受击、接剑等短促强调。

## 1. 风格目标

### 核心画面

一张 16:9 横向战场中，黑影剑修在画面左中或中部偏左高速穿行。角色身体压低，手部仍保持控剑或引阵姿态。飞剑和剑阵是最高亮度主体。背景是低亮度水墨云山、纸纹、墨雾、飞白风痕，不抢角色和攻击。

### 关键词

```text
水墨剪影，黑影小人，飞白风痕，宣纸颗粒，墨雾远山，横向空域，低饱和背景，高亮飞剑，冷白剑光，淡金阵线，绯红敌方威胁，速度留白，清楚轮廓，动作意图优先
```

### 禁止项

```text
不要页游仙侠大翅膀
不要复杂五官和精细服装花纹
不要赛博霓虹驾驶舱
不要飞机、导弹、机甲、驾驶舱、喷气尾焰
不要厚重 UI 面板
不要把背景画成高细节写实山水
不要厚涂仙侠立绘和高细节彩色主角
不要全屏高亮水墨导致战斗主体不可读
不要全屏发光技能遮住角色手部和剑阵形态
不要直接复制 Jet Lancer 的飞机、像素材质、配色和 UI
```

## 2. Jet Lancer 参考的抽象规则

只借鉴布局和读屏，不借鉴具体资产：

- 横向高速空域，而不是静态单屏地面。
- 玩家主体通常保留在画面左中到中心区域，前方留出攻击和反应空间。
- 画面边缘承担威胁预告，敌人、弹幕、Boss 身体从远端进入。
- 背景用强视差表达高速，近景快、中景稳、远景慢。
- 战斗信息靠大轮廓和高对比读清，不靠角色细节读清。

落到本项目：Jet Lancer 的“喷气空战”要转换成“御剑空战”。画面不是飞机冲刺，而是剑修身法、风压、飞剑轨迹和剑阵扩张。

## 3. 画布与战场布局

### 基准画布

- 设计画布：`1920 x 1080`
- 游戏内参考：16:9 横向战场，可缩放到当前 Godot 画布。
- 玩家活动带：画面左 25%-55%，纵向 20%-80%。
- 攻击预读区：画面右 45%-100%，用于敌人、弹幕、Boss、剑阵远端目标。
- 危险预告区：屏幕四边 8%-12% 内，用绯红墨印、边缘墨裂、朱砂牵引痕提示入场。
- Ring 压力区：玩家周围 0%-18% 半径内必须支持上下、背后、贴身进入的敌方预告，避免横向空战只服务远程 Fan/Pierce。

### 场景层

```text
L0 paper_base        宣纸底纹，低对比，不滚动或极慢
L1 far_mountains     远山/云痕，慢速视差
L2 ink_clouds        墨云、雾带，中速视差
L3 wind_streaks      飞白风线，高速视差
L4 combat_plane      角色、剑、敌人、弹幕、剑阵
L5 impact_ink        命中墨爆、屏幕边缘墨裂、瞬时高亮
L6 hud_marks         轻量法印 HUD，不做厚面板
```

### 可读性规则

- 角色本体是黑影，但手部、剑柄 socket、剑阵引导线必须能被看见。
- 友方攻击：冷白、青白、淡金。
- 敌方威胁：绯红、暗红、朱砂高亮核心。
- 背景亮度永远低于角色轮廓和飞剑。
- 任何 128px 以内的小尺寸缩略图中，玩家、飞剑方向、敌方威胁三者仍要能分辨。
- 玩家周围必须保留局部浅纸色负空间或低 alpha 墨雾避让，禁止黑影角色被背景/Boss 墨影吞掉。
- Boss 墨影靠近玩家时必须降低 alpha、留出剪影空洞，或通过 shader 避让玩家 48-96px 范围。

### 亮度层级

从暗到亮：

```text
L0 背景纸纹/远山
L1 远景墨雾
L2 残影和低速风线
L3 玩家黑影主轮廓
L4 敌方朱砂预告/弱点
L5 友方飞剑冷白刃光/剑阵主线
L6 命中、parry、释放峰值
```

约束：

- L6 峰值持续不超过 0.12s，且不得大面积铺满屏幕。
- 友方剑光保持纸面飞白和冷白刃口，不做霓虹光棒。
- 手部意图高光优先级高于衣摆、残影、背景风线。

### 4.1.1 V15.1 可选拆件扩展

以下拆件用于增强高速压低、急转和手部读屏，不能在 P0 未改 loader 时进入 runtime `parts`。它们先作为 `source/optional_split_parts/` 的美术源文件或 V15.1 `part_sets.split_limb_v15` 使用：

```text
resources/flight/rider/body_v15_ink_rig/

      leg_front_thigh.png
      leg_front_calf.png
      leg_back_thigh.png
      leg_back_calf.png

      hand_back_intent_highlight.png
      robe_front_root.png
      robe_front_tip.png
      robe_back_root.png
      robe_back_tip.png
      torso_chest.png
      torso_waist.png
```

推荐优先级：

```text
必须优先验证：leg_front_thigh / leg_front_calf / leg_back_thigh / leg_back_calf
强烈建议：hand_front_intent_highlight / hand_back_intent_highlight
建议：robe_front_root / robe_front_tip / robe_back_root / robe_back_tip
暂不强制：torso_chest / torso_waist
```

拆分原则：

- 大腿/小腿建议拆；脚 P0 不单独拆，先烘进 `leg_*_calf`，用脚尖形状表达拖拽方向。
- 不做完整写实三段腿骨，不拆脚趾；黑影小人的腿部要保持一眼可读的大轮廓。
- 手部意图高光层必须能置顶或加亮，保证高速残影、衣袖、Overlay 峰值都不能盖掉 `hand_front / hilt / aim_forward`。
- 衣摆最多拆成 root/tip 两段，不超过前后各两片；飘带已有 root/mid/tip，不再继续细拆。
- 若启用 split limb runtime，必须隐藏对应复合件 `leg_front` / `leg_back`，避免双重绘制。

角色颜色：

```text
主轮廓：近黑 #050505 到 #111111
软边墨晕：黑色 25%-45% alpha
手部意图高光：冷白/淡青 1-2px 细线或微光，允许覆盖手部面积 8%-22%
阵法反光：淡金，极弱，只在释放/转阵瞬间出现
```

手部规则：

- 手部、剑柄、`aim_forward` 是操作意图锚点，不能被高速压低、残影或风线盖掉。
- 禁止把手画成大面积发光手套；高光只服务轮廓、指向和剑柄连接。
- 128px 缩略图中必须看出“手在控剑/引阵”的方向。

### 4.1.2 Manifest Schema

`body_v15_ink_rig_manifest.json` 沿用 V14 schema：

```json
{
  "source": "source/body_v15_ink_exploded_parts_clean.png",
  "source_size": [2048, 2048],
  "padding": 4,
  "parts": {
    "torso": {
      "file": "parts/torso.png",
      "size": [322, 448],
      "pivot": [161.0, 80.6],
      "source_bbox": [66, 265, 388, 713]
    }
  }
}
```

要求：

- P0 runtime `parts` 必须等于 4.1 的 21 个 core 部件。
- V15.1 新增拆件必须放进 `optional_parts` 或 `part_sets.split_limb_v15`，不能直接混进 P0 `parts`。
- `pivot` 是该部件 PNG 内的像素坐标，Godot y-down。
- `source_bbox` 是部件在 exploded source 内的 `[x0, y0, x1, y1]`。
- 所有部件 PNG 必须透明背景，不能带纸底。

V15.1 optional schema 示例：

```json
{
  "parts": {
    "leg_front": {"file": "parts/leg_front.png"}
  },
  "optional_parts": {
    "leg_front_thigh": {"file": "parts_optional/leg_front_thigh.png"},
    "leg_front_calf": {"file": "parts_optional/leg_front_calf.png"},
    "hand_front_intent_highlight": {"file": "parts_optional/hand_front_intent_highlight.png"}
  },
  "part_sets": {
    "core_v14": ["torso", "hair_back", "hair_tail"],
    "split_limb_v15": ["leg_front_thigh", "leg_front_calf"]
  }
}
```

### 4.1.3 Pose Library Schema

`body_v15_ink_pose_library.json` 沿用 V14 schema：

```json
{
  "format_version": 1.0,
  "coordinate_system": "pivot offsets in pre-scale pixel units, y-down (Godot)",
  "assembly_scale": 0.18,
  "poses": {
    "idle": {
      "torso": {
        "position": [0.0, -820.0],
        "rotation_degrees": 0.0,
        "scale": [1.0, 1.0],
        "z_index": 0
      }
    }
  }
}
```

要求：

- 每个 pose 必须包含当前 active part set 的全部部件；P0 core 模式下就是 21 个 core 部件。
- 如果 V15.1 启用 split limb，必须有显式隐藏/禁用复合腿部的策略，不能靠 `scale: [0, 0]` 隐藏，因为当前 runtime 尚未应用 scale。
- `position` 是该部件 pivot 相对角色 root 的预缩放像素偏移。
- `rotation_degrees` 使用 Godot 角度，顺时针为正的视觉结果以实际预览为准。
- `z_index` 必须稳定，不允许同一部件在相邻 pose 中无理由跨层跳变。
- `assembly_scale` 第一版沿用 `0.18`，除非实现同步调整。

### 4.1.4 Socket Library Schema

`body_v15_ink_socket_library.json` 提供持续 pose 与序列帧 socket：

```json
{
  "format_version": 1.0,
  "coordinate_system": "local pixels before assembly_scale, y-down",
  "poses": {
    "sword_control_idle": {
      "root": [0.0, 0.0],
      "chest": [0.0, -820.0],
      "head": [0.0, -1180.0],
      "hand_front": [240.0, -460.0],
      "hand_back": [-180.0, -520.0],
      "hilt": [260.0, -470.0],
      "aim_forward": [1.0, 0.0]
    }
  },
  "sequences": {
    "array_ring_release_12": [
      {
        "frame": 0,
        "root": [0.0, 0.0],
        "chest": [0.0, -820.0],
        "head": [0.0, -1180.0],
        "hand_front": [230.0, -470.0],
        "hand_back": [-160.0, -520.0],
        "hilt": [250.0, -470.0],
        "aim_forward": [1.0, 0.0]
      }
    ]
  }
}
```

要求：

- `aim_forward` 是单位向量。
- 镜像时 x 坐标取反，`aim_forward.x` 取反。
- 相邻帧 `root` 跳变不得超过 2px；`hilt` 跳变不得超过 8px，除非该帧标记为 impact/flash。
- 所有序列首尾 socket 必须能接回对应 rig pose。
- V15.1 可追加 `waist`, `pelvis`, `knee_front`, `ankle_front`, `foot_front`, `knee_back`, `ankle_back`, `foot_back`，但 `root/chest/head/hand_front/hand_back/hilt/aim_forward` 的语义名不能改。

### 4.2 Rig 持续姿态

这些用部件 rig 做，不画完整序列帧：

```text
idle
move_forward
move_back
high_speed_crouch
turn_lean_left
turn_lean_right
sword_control_idle
array_ring_idle
array_fan_idle
array_pierce_idle
array_hold
```

要求：

- 身体可以被高速压低，手部不能丢失控剑/引阵意图。
- 高速姿态的压低幅度控制在角色总高的 6%-14%。
- 转向姿态只改变身体倾斜、衣摆拖拽和头肩方向，不覆盖手部动作。
- 右键御剑持续姿态优先保持手与剑柄 socket 的稳定。
- 右键御剑拆为三态视觉：`sword_control_idle` 表达持续控剑，`sword_control_commit` 表达主动发令，`sword_return_catch` 表达飞剑回手。
- 急转时 `aim_forward`、手部 socket、飞剑方向三者必须连续，残影禁止覆盖手部/剑柄区域。

```text

  array_ring_release_12.png
  array_fan_release_12.png
  array_pierce_release_12.png
  array_ring_to_fan_12.png
  array_fan_to_pierce_12.png
  array_pierce_to_ring_12.png
  sword_control_commit_8.png

  parry_10.png
  hurt_8.png

```

序列帧规格：

- 单帧：`256 x 256` 透明 PNG。
- 动作条：横向 strip，`frame_count * 256 x 256`。
- `FrameOverlay` 坐标以角色 root 为中心，单帧中心点默认为 `(128, 128)`。
- 不混入 V13/V13_1 16 帧行式 atlas。
- 每帧 socket 写入 `body_v15_ink_socket_library.json` 的 `sequences`。
- Overlay 播放时 rig 可隐藏或降低 alpha，但 rig root、速度、朝向和 socket 仍在后台更新。

Overlay manifest 示例：

```json
{
  "format_version": 1.0,
  "frame_size": [256, 256],
  "sequences": {
    "array_ring_release_12": {
      "file": "array_ring_release_12.png",
      "frames": 12,
      "fps": 24,
      "entry_pose": "array_ring_idle",
      "exit_pose": "array_ring_idle",
      "endpoint_hold": [0.08, 0.10],
      "peak_frames": [4, 8],
      "frame_tags": {
        "4": ["impact"],
        "5": ["flash"],
        "6": ["flash"]
      }
    }
  }
}
```

要求：

- `entry_pose` / `exit_pose` 必须同时存在于 pose library 和 socket library。
- 只有带 `impact` 或 `flash` tag 的帧可以突破普通 `hilt` 连续性限制。
- `peak_frames` 只能短时增强，不得遮住手部意图高光和近身 Ring 轮廓。

### 4.4 序列帧切回 Rig 的要求

- 序列帧第一帧要接近对应 rig 起手姿势。
- 序列帧最后一帧要能接回 `sword_control_idle` 或对应 `array_*_idle`。
- 释放动作允许用 1-2 帧墨闪遮缝，但不能用全屏闪白。
- `root` 位置、朝向、手部 socket 不得跳变。
- 切回 rig 时必须用最后一帧 `hilt` / `hand_front` / `aim_forward` 初始化接续姿态，再在 2-6 帧内混回持续 pose。

## 5. 飞剑与剑阵资产

### 5.1 飞剑本体

```text
sword_ink_core_01.png        细长黑心、冷白刃光

sword_ink_broad_01.png       fan 扫掠版本
```

## 12. 验收标准

### 画面风格

- 一眼是水墨剪影修仙，不是彩色仙侠立绘。
- 一眼能看出横向高速空战布局。
- 角色是黑影，但操作意图不黑成一团。

### 战斗可读性

- 右键御剑、剑阵释放、高速移动、高速转向可以同时成立。
- 玩家手部意图不被高速压低姿态覆盖。
- Ring/Fan/Pierce 三形态在 0.2s 内可辨认。
- 敌方红色威胁和友方冷白剑光不会混色。
- 右键御剑的 `hold/control`、`commit`、`return/catch` 三态能在实机中读出不同意图。
- 急转时 `aim_forward`、手部 socket、飞剑方向保持连续。
- Ring 至少有一类上下/背后/贴身压力场景能证明近身可靠性。
- 残影、风线、Boss 墨影不得遮盖手部、剑柄和近身 Ring 轮廓。

### 技术接入

- Rig 部件 pivot 清楚，命名稳定。
- 序列帧 root 和 socket 连续。
- 背景分层可视差滚动。
- 所有 PNG 提供透明背景版本。
- 文件命名与本任务包一致。
- V15 rig manifest/pose library 能被 V14 rig loader 以最小改动读取。
- P0 `body_v15_ink_rig_manifest.json` 的 runtime `parts` 等于 V14 21 个 core 部件；optional split 不参与首轮运行时加载。
- FrameOverlay manifest 能提供 frame size、fps、entry/exit pose、endpoint hold 和 peak frames。
- Socket library 覆盖 P0 所有 pose 与 overlay 序列。
- 背景 layer json 能直接驱动滚动因子、alpha、repeat 和 blend mode。
- V15.1 启用 optional split 时，必须支持 active part set、复合腿隐藏、手部高光置顶和 pose 缺项校验。

## 13. 不达标判定

出现以下任一情况，应退回：

- 角色变成彩色高细节主角，失去黑影剪影方向。
- 背景山水过亮、过密，战斗主体读不出来。
- 高速姿态把手部动作压没，右键御剑和剑阵释放无法区分。
- 剑阵三形态只靠颜色区分，没有轮廓/运动差异。
- Jet Lancer 参考被误解成复制飞机、导弹和科幻 UI。
- P0 runtime manifest 使用非 V14 core 部件命名，导致现有 rig loader 或校验器无法识别。
- 新增大腿/小腿/脚/胸腰拆件直接混入 P0 `parts`，没有 optional part set 和隐藏策略。
- 序列帧没有 socket metadata，无法稳定接回 rig。
- P0 没有 Ring 近身压力场景，只展示远程横向输出。
